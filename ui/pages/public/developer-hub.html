Technical architecture · HLD

Browser pages are routed through web.config and ui/router.php. Versioned API requests are allow-listed through api/web.config and api/core/Router.php. Modules use shared security, session, CSRF, configuration, and database services before returning JSON.

Public / Admin UI → IIS rewrite → UI router or /api/v1 router
                         ↓
              Security + Session + CSRF + Validation
                         ↓
       Auth | QR | Public Survey | Analytics | Profile modules
                         ↓
             MySQL data + JSON survey master configuration

Low-level design · service map

  • api/core/: headers, response format, router, CSRF, sessions, error handling.
  • api/modules/*/v1/: versioned request handlers.
  • api/helpers/SurveyConfig.php: QR reference, survey content, radius, and distance calculation.
  • ui/assets/js/: survey interaction, administrator pages, token handling, and accessibility behaviour.
  • api/masters/: facility, department, question, button, message, and radius configuration.

Survey master JSON: facilities · departments · questions · labels · radius

Apply database migrations from api/database/migrations/, including the login rate-limit migration, before production deployment.

Security, VAPT and deployment

Implemented controls include secure host-only session cookies, CAPTCHA, five-attempt fifteen-minute login lockout, CSRF for authenticated write actions, CSP, anti-clickjacking, HSTS, no-store caching, and IIS technology-header suppression. Production requires HTTPS, restricted database access, application-pool recycle, and VAPT retesting.

Open source and Digital Public Good validation

GPL-3.0 provides an OSI-approved open-source license. DPG readiness still requires named ownership and governance, SDG impact evidence, privacy and retention policy, non-PII data-export documentation, interoperability evidence, and an independently verified production security assessment.
