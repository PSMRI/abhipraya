Developer architecture guide

Reference architecture, implementation boundaries, security controls, deployment responsibilities, and operational flows for Abhipraya.

User guide summary

Administrators sign in, select a facility and department, generate QR posters, review feedback trends, and prepare CAPA actions. Survey participants scan the facility QR code, permit location validation, select a language, and submit anonymous feedback.

User flows

ImproveCreate CAPA actions.

Primary use cases

Facility feedback

  • QR-led anonymous public survey.
  • Language selection and location validation.
  • Department-specific questions and thank-you messages.

Service improvement

  • Trend and indicator reporting.
  • QR management for facility teams.
  • Corrective and preventive action planning.

High-level architecture

Abhipraya separates browser-facing pages, an allow-listed API, survey master data, and persistent storage. IIS supplies routing and security headers; PHP owns business rules and session protection.

Core flows

1. QR scanParticipant opens `question.php?nin=FACILITY_NIN_DEPARTMENT_ID`.
2. ResolveSurvey API validates facility, department, and question configuration.
3. LocationBrowser supplies GPS; API calculates distance against the configured radius.
4. SurveyUser selects language, answers questions, and submits.
5. PersistAPI validates payload, prevents duplicates, then stores response data.
1. LoginCaptcha and credentials are submitted to the auth API.
2. ThrottleFive failed username/IP attempts lock access for fifteen minutes.
3. SessionSecure session ID is regenerated after valid authentication.
4. CSRFAuthenticated write actions obtain and send a CSRF token.
5. Admin workDashboard, QR, report, profile, and CAPA APIs enforce session controls.

Security and deployment checklist

Application controls

  • CSRF on authenticated write endpoints.
  • HttpOnly, SameSite=Strict session cookies.
  • HTTPS-only Secure cookies in production.
  • Captcha, delay, and database-backed login lockout.
  • Location-gated survey submission.

IIS and operations

  • Use HTTPS and redirect HTTP traffic.
  • Apply VAPT header configuration in both web.config files.
  • Apply all database migrations before release.
  • Keep `.env` outside public source control.
  • Recycle the application pool after deployment and retest.

Open-source validation

Abhipraya uses GPL-3.0, an OSI-approved license. The repository now includes a README, contributing guidance, security reporting guidance, user/developer documentation, and a public license. Before public release, publish named maintainers, release/versioning policy, code of conduct, and an issue tracker.

DPG validation

DPG readiness is partial: open licensing and documentation foundations are complete. The remaining evidence includes SDG 3 impact, asset ownership, platform-independence guidance, non-PII export design, privacy/retention policy, interoperability standards, and an independently verified production security assessment.

Before nomination: publish governance and privacy policy, document SDG impact and data practices, then complete a production VAPT retest.
